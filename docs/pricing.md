# 定价与 Key 策略（当前阶段）

结论先说：**两条路都可用，平台代付会贵一点，自带 Key 永远不占平台额度。**
现阶段不做订阅收费，只把规则讲清楚，避免用户把「免费额度」误解成「无限免费」。

## 两种入口

| 入口 | 出题模型 | 判定模型 | 计费 | 适用 |
| --- | --- | --- | --- | --- |
| 平台代付 | 平台 Key（OpenAI 兼容） | 平台 Jev Key | 按使用量记到平台成本，默认设每日熔断 | 想立刻上手、不愿自己申请 Key 的用户 |
| 自带 Key（BYOK） | 用户自己的 DeepSeek / GLM / Qwen / Kimi / OpenAI 等 | 用户自己的 Jev Key | 用户直接付给服务商，平台不代付、不抽成 | 已有 Key、想控制成本或走国内服务的用户 |

平台代付“贵一点点”的含义：平台需要在模型成本之上覆盖垫资、缓存、限流与运营成本，
所以同等用量会比用户自己直接调模型略贵；具体差价在真实计费上线时按服务商账单回算。

## MVP 为什么不急着收费

1. 当前没有真实用户，收费系统只会增加交付风险；
2. 平台的每日额度与消费熔断已经能防住“被刷到亏钱”；
3. 先证明用户愿意上传自己的材料，再谈按材料页数 / 答疑次数 / 复习时长分级。

## 将来计费建议（不要现在实现）

- 免费层：少量材料 + 少量出题 + 少量答疑，用于体验闭环；
- 按量层：按“材料页数 + 出题数 + 答疑次数”组合计费；
- 自带 Key：永远允许，且不计平台额度，但核心功能（判定门控、溯源、复习）仍保留。

## 成本护栏

- 单人模型消费上限：`DAILY_SPEND_CAP_MICRO_USD`（默认 $0.50/人/天，平台 Key）；
- 全平台消费熔断：`PLATFORM_DAILY_SPEND_CAP_MICRO_USD`（默认 $10/天，平台 Key）；
- 每日次数额度：材料 / 出题 / 判定 / 问答分别限量；
- 所有阈值集中在 `src/lib/config.ts`，BYOK 不占平台额度、不受平台熔断。
